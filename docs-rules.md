# 📚 Documentation & Code Style Rules

## 1. Общие принципы написания текстов
* **Принцип «Пиши, сокращай»:** Убирай канцеляризмы, вводные конструкции и воду. Каждое предложение должно нести прикладной смысл[cite: 6, 8].
* **Тон коммуникации:** Профессиональный, дружелюбный, лаконичный[cite: 6, 8].
* **Структура и визуал:** Используй маркированные списки и умеренные эмодзи в качестве смысловых якорей (🔒 безопасность, 📦 база данных, ⚡ производительность, 💳 оплата)[cite: 6, 8].

## 2. Документирование кода (TSDoc / JSDoc)
* Каждый публичный метод, серверный эндпоинт и утилита должны сопровождаться блоком TSDoc[cite: 7].
* Обязательно документировать:
  * Назначение функции[cite: 7].
  * Входные параметры (`@param`) и возвращаемые типы (`@returns`)[cite: 7].
  * Сайд-эффекты (например: «Выполняет запись в таблицу `orders` и шлет событие в Supabase Realtime»)[cite: 7].
  * Тег безопасности `@security` для любых функций, проверяющих права, HMAC, или санитизирующих ввод[cite: 5, 6].
